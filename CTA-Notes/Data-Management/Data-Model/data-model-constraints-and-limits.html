Exceptions and hard limits in the Salesforce data model that change a solution decision — things that look possible on a whiteboard but aren’t (e.g. “route Assets through a queue”). Complements standard-object-oddities (standard-object quirks) and data-model (ERDs and design guidance).

Exam framing

When you pick an object or relationship, check it against this list before you commit. If a constraint bites, say so in the board answer and name the workaround — it shows you know the platform’s edges.

Ownership & Queues

Ownership drives sharing, queues, assignment rules, and Omni-Channel routing, so “can this object be queue-owned?” is a frequent make-or-break question.

Who can own what

The Object Reference shows each object’s OwnerId target type. If it refers to User only, the record cannot be owned by a queue.

Owner can be…Standard objects (Object Reference v63.0)Solution impact
User onlyAccount, Contact, Campaign, Contract, Asset, Solution, Individual; also Note, ContentDocument, ContentVersionNo queue ownership → no queue-based work distribution, no assignment-rule-to-queue, no queue-based Omni-Channel routing for these records
User or Group (queue)Case, Lead, Order, Task, Work Order, Service Appointment, Contact Request, Incident, Problem, Swarm, Messaging Session, Voice Call, Return Order, Fulfillment Order, Location, and othersQueue ownership is possible — confirm the object is enabled for the queue in Setup
User or CalendarEventEvents can’t be queue-owned; the owner can be a calendar
Custom objectsQueueSobject supports custom objects (Object Reference — QueueSobject)A custom object is the usual escape hatch when you need queue ownership

"Refers To: Group" ≠ queue-enabled

The Object Reference tells you the owner field can point at a Group. Whether you can actually add the object to a queue is set up per queue (Setup → Queues → Supported Objects). The earlier, shorter queue-ownable list in standard-object-oddities is a subset of what the Object Reference shows — verify in the org before relying on either. This note did not verify Opportunity, Quote, Product, Entitlement, or Service Contract.

Master-detail children have no owner

  • On the detail side of a master-detail relationship the Owner field isn’t available; the record takes the master’s owner.
  • Custom objects on the detail side can’t have sharing rules, manual sharing, or queues, because those require the Owner field.
  • Detail records inherit security from the master and you can’t set permissions on the detail independently.
  • (Object Relationships Overview)

Board takeaway

For Asset, Account, Contact, Campaign, and Contract: “queues aren’t supported on the object, so work distribution runs through a queue-ownable record (Case/Work Order/custom) that references it.”

Silent security change

Converting M-D ↔ lookup changes the child’s OWD. Re-check sharing and external access before and after.

Reporting Impact

RelationshipStandard report types
LookupTwo objects joined in one report
Master-detailMaster + detail + one other lookup (three objects)
Many-to-manyTwo report types joining the primary/secondary master and junction; master order matters (the first master defines the record scope)
  • Multilevel master-detail uses custom report types; they count toward the org’s custom report type limit, and no reports generate if the limit is exceeded.
  • Cross-object reporting beyond these joins needs custom report types or analytics — see reporting.

External Object Relationships

(Considerations for Object Relationships)

  • Only lookup, external lookup, and indirect lookup relationships are available for external objects.
  • No cascade delete on external object relationships.
  • Lookup search isn’t available for external lookup or indirect lookup fields — users type the External ID / target field value manually (not applicable for the cross-org adapter on external lookup).
  • Lookup filters aren’t available for external lookup fields.
  • Indirect lookup fields can be created on external objects only, and the parent needs a custom field that is External ID + Unique (case-sensitive match if the source is case-sensitive).
  • Related lists of child external objects can load slowly when the external system is slow or unavailable.
  • Creating a child record from the parent detail page doesn’t auto-populate the relationship field.
  • Relationship fields can be overwritten when you sync the external object.
  • Salesforce Connect external objects are an extra-cost add-on for Enterprise, Performance, and Unlimited editions.

See 32-salesforce-connect for the adapter side.

Deployment Gotchas

Relevant to environment-strategy and data-migration:

  • A Metadata API deployment that adds or converts to a master-detail field permanently deletes detail records in the Recycle Bin — soft-delete or populate parents first, or the deployment fails.
  • A profile/permission set with a master-detail child entity can have a broken permission dependency (e.g. child View All requires parent View All); Salesforce fixes the parent on the first save.
