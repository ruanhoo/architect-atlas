What It Is

Partner Contact Center (formerly Service Cloud Voice / Salesforce Voice) is Salesforce’s native CCaaS (Contact Center as a Service) capability — it brings telephony into the Service Console as just another Omni-Channel work item, alongside case, chat, email, and messaging.

Naming history

Service Cloud Voice → Salesforce Voice → Partner Contact Center. Expect exam/vendor material to use any of these names interchangeably. “Partner” refers to the telephony partner model (bring-your-own-telephony or Amazon Connect), not a Partner Community concept.

Core Value Proposition

  • Telephony, digital channels, and CRM data unified on one platform (Agentforce Service / Service Console) instead of a CTI screen-pop bolted onto a separate phone system
  • Real-time voice transcription → feeds Einstein for next-best-action and knowledge article recommendations mid-call
  • Supervisors get real-time Omni-Channel visibility into calls, analytics, and rep performance (Omni Supervisor)
  • No-code phone channel setup, plus choice of telephony provider

Partner Contact Center vs. CTI (Exam Angle)

DimensionPartner Contact CenterCTI
Integration modelNative to platform; Amazon Connect out-of-box or AgentExchange partnerThird-party telephony package installed per computer
Data captureAutomatic transcription populates records; AI-driven next actionsManual note-taking; limited automation
Console experienceOne Omni-Channel widget for all channelsSeparate call-control tool in console footer
Supervisor visibilityOmni Supervisor sees all channels + live call transcriptsLimited to call-specific analytics

When architecting: CTI still shows up in the field, but for new implementations the default recommendation should be Partner Contact Center — flag CTI only when there’s a hard constraint (unsupported region/provider, existing multi-year telephony contract, or M&A carve-out timeline).

Prerequisites & Constraints (worth memorizing for boards)

  • Lightning Experience only (no Classic)
  • Add-on license on top of Service Cloud or Sales Cloud
  • Browser support limited to Chrome and Firefox; cookies required for SSO
  • Requires a custom domain + SSO URL, and Omni-Channel enabled before Voice is turned on
  • If using Amazon Connect telephony: review/increase AWS service quotas — max concurrent calls, max transcription jobs, outbound-callable country list
  • Sequencing: set up case management (fields, assignment rules, routing) before adding Voice — adding a phone channel on top of an immature case model just moves the chaos into real time

Implementation Planning Checklist

  1. Baseline current state: phone system, number of call centers, phone number inventory, license/seat count, who needs Omni Supervisor access
  2. Decide telephony model (table above) — this is a purchasing decision, not just a technical one; needs someone authorized to buy
  3. Number porting — start early; regulated, provider-dependent, cannot be rushed against a go-live date
  4. Environment/testing strategy — sandbox count, Amazon Connect test instances, prod↔test data migration plan
  5. AWS networking review if using Amazon Connect (don’t block required ports)
  6. Routing design — map existing case assignment/skills-based/queue routing onto Omni-Channel routing; decide how much of the current IVR logic carries over
  7. Reporting/analytics — Voice ships a contact center dashboard (call volume, AHT, average speed to answer, resolution %); decide what custom reports are still needed beyond it
  8. Rep enablement — training on Omni-Channel widget vs. old softphone, call scripts, brand voice/tone (not just tooling: this is a change-management stream)

Trade-off Considered: Voice vs. Staying on CTI

  • CTI: lower short-term disruption, but caps the org’s ability to use AI (next best action, transcription-driven knowledge surfacing) because CTI call data isn’t native to the platform
  • Partner Contact Center: higher setup cost (porting, AWS quotas, retraining) but unlocks Omni-Channel-native routing, AI, and unified supervisor tooling — the CTA case for switching hinges on whether AI-driven service and unified reporting are strategic priorities, not just “can reps make calls”
