(Salesforce Integration Patterns and Practices)

The Six Canonical Patterns

1. Remote Process Invocation — Request and Reply

Salesforce invokes an external process synchronously and waits for the result before continuing.

DimensionDetail
DirectionSalesforce → External
TimingSynchronous
TechnologiesApex callout (REST/SOAP), External Services + Named Credentials
When to useResult is needed immediately to complete the Salesforce transaction (e.g. credit check, address validation, real-time pricing)
Key constraint120s callout timeout; avoid in triggers without async wrapper

Warning

Never make a synchronous callout from a trigger directly — wrap in @future(callout=true) or Queueable if the result is not needed before the DML commits.

2. Remote Process Invocation — Fire and Forget

Salesforce triggers an external process asynchronously and does not wait for the result.

DimensionDetail
DirectionSalesforce → External
TimingAsynchronous
TechnologiesPlatform Events, Outbound Messaging (legacy), @future(callout=true), Queueable
When to useExternal process doesn’t need to return data to Salesforce immediately (e.g. trigger a workflow in an external system, send a notification)
Key constraintAt-least-once delivery with Platform Events; retry logic needed for callout-based approaches

3. Batch Data Synchronization

Large volumes of data are moved between Salesforce and an external system on a scheduled basis.

DimensionDetail
DirectionBoth
TimingAsynchronous / scheduled
TechnologiesBulk API 2.0, MuleSoft/ESB, Scheduled Apex + SOQL, CDC with batch catch-up
When to useNightly syncs, data migrations, periodic reporting extracts
Key constraintHandle duplicates and conflict resolution; define the system of record

4. Remote Call-In

An external system calls Salesforce to query or modify data.

DimensionDetail
DirectionExternal → Salesforce
TimingSynchronous
TechnologiesREST API, SOAP API, Bulk API 2.0, GraphQL, UI API
When to useExternal system needs to read or write Salesforce data on demand (e.g. ERP pushing orders, mobile app reading records)
Key constraintAuthentication (OAuth 2.0), API limits, FLS enforcement

5. UI Update Based on Data Changes

The Salesforce UI or an external UI updates in real time when data changes.

DimensionDetail
DirectionSalesforce → Client (browser/app)
TimingNear-real-time / event-driven
TechnologiesPlatform Events + LWC empApi, CDC + CometD/Pub/Sub API, Streaming API
When to useLive dashboards, real-time notifications, collaborative editing indicators
Key constraintCometD/empApi is browser-only; Pub/Sub API for external systems

Note

CDC is applicable here for data-change-driven UI updates. PE is applicable when the trigger is a business event, not necessarily a record save.

6. Data Virtualization

Salesforce displays data from an external system without storing it locally.

DimensionDetail
DirectionExternal → Salesforce (on demand)
TimingSynchronous (at read time)
TechnologiesSalesforce Connect (External Objects), OData adapter, Custom Apex adapter
When to useData lives in an external system and must not be duplicated; real-time accuracy required; data is too large to copy
Key constraintNo sharing model on external objects; no triggers; latency depends on external system; OData or Apex adapter required
