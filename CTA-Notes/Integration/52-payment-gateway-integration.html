Integration Approaches

There are two main ways to integrate a payment gateway with Salesforce:

1. Salesforce Payments (Native)

  • Built-in payment processing via Stripe (for Commerce Cloud / Experience Cloud orgs)
  • No custom integration code required
  • Supports card payments, refunds, and payment method management natively
  • Tied to Salesforce Commerce Cloud / B2B Commerce

2. Custom Gateway Integration (Apex callout)

  • Salesforce calls the payment gateway’s REST/SOAP API via Apex callout
  • Use Named Credentials to store endpoint + auth credentials securely
  • Payment result returned synchronously (RPI Request-Reply pattern)
  • Store transaction result on a custom object or Order/Payment record

Architecture Considerations

Never process card data through Salesforce

  • Salesforce is not PCI-DSS certified as a card data environment
  • Card number, CVV, expiry must go directly from the browser to the gateway (client-side tokenisation)
  • Salesforce only receives and stores the payment token (non-sensitive)

Tokenisation Flow

Browser → Payment Gateway JS SDK → Gateway returns token
Browser → Salesforce (token only, no card data)
Salesforce Apex → Gateway API (charge token) → Result stored in Salesforce

Recommended Pattern

  • RPI Request-Reply for synchronous payment authorisation
  • RPI Fire-and-Forget for async notifications (e.g. webhook from gateway → Platform Event → Salesforce order update)

Webhook Handling (Gateway → Salesforce)

Most gateways send webhook notifications for async events (payment captured, refund processed, dispute raised):

  1. Gateway POSTs to a Salesforce endpoint
  2. Use a Site (Experience Cloud guest user endpoint) or Connected App to receive the webhook without requiring OAuth user auth
  3. Validate the webhook signature in Apex before processing
  4. Publish a Platform Event or call a Flow to process the notification asynchronously

Warning

Validate webhook signatures (e.g. Stripe uses Stripe-Signature HMAC). Never process a webhook payload without verifying it came from the legitimate gateway.

Key Objects for Storing Payment Data

  • Order + OrderPaymentSummary (Order Management)
  • Custom Payment_Transaction__c object if not using Order Management
  • Store: gateway token, transaction ID, amount, status, timestamp — never card number or CVV
