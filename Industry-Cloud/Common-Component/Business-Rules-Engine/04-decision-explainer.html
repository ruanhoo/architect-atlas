Decision Explainer

Decision Explainer

Nov 28, 20268 min read

  • industry-cloud
  • business-rules-engine
  • decision-explainer
  • explainability

A service that records and surfaces why a business rule produced a specific result. Part of 01-business-rules-engine-overview.

Purpose

  • Setup objects capture logs of how a rule or 02-expression-sets ran
  • Reviewers can explain outcomes to end users (e.g. why a student got a smaller discount than expected)
  • Auditors can compare two expression set runs to see what changed
  • External users (applicants, customers) can see readable explanations in the UI without seeing the internal rule logic

Key objects:

  • ExplainabilityActionLog — one log per expression set run; linked to the context record (e.g. the application or case)
  • ExplainabilityStepLog — one log per step that has “Show decision explanation” enabled; stores the rendered message
  • ExplainabilityMsgTemplate — reusable message templates with placeholders (tokens)
  • ExpressionSetMessageToken — maps template placeholders to expression set variables/outputs

Key fields:

  • ContextRecordId — the object record the expression set ran for (e.g. Application__c record ID); links the log to the UI
  • ActionContextCode — unique identifier for a single expression set run
  • ResultType — Passed (step returned output), Failed (step errored), NoResult (Lookup Table found no match)
  • ExplanationMessage — the final rendered message with token values substituted

Process Flow: How Explanation Data is Generated

sequenceDiagram
    participant Flow as Flow / API Caller
    participant ES as Expression Set
    participant Step as Expression Set Step
    participant DE as Decision Explainer
    participant Log as ExplainabilityActionLog
    participant UI as Decision Explainer<br/>Log History Component
    
    Flow->>ES: Invoke expression set<br/>(with actionContextCode)
    ES->>DE: Create ActionLog<br/>(ContextRecordId, ActionContextCode)
    
    loop For each step with "Show decision explanation" enabled
        ES->>Step: Execute step
        Step->>Step: Evaluate condition /<br/>perform calculation
        Step-->>ES: Return result + outputs
        ES->>DE: Create StepLog<br/>(StepName, ResultType)
        DE->>DE: Render message template<br/>(substitute token values)
        DE->>Log: Save ExplanationMessage
    end
    
    ES-->>Flow: Return outputs + ActionContextCode
    Flow->>UI: User views record page
    UI->>Log: Query logs by ContextRecordId
    Log-->>UI: Display explanation messages
    
    Note over UI,Log: User can compare two runs<br/>by selecting multiple ActionLogs

Step-by-step:

  1. Flow invokes expression set: passes actionContextCode and explainabilitySpecName in the API call
  2. Decision Explainer creates ActionLog: linked to the ContextRecordId (the object record)
  3. For each enabled step:
    • Expression set executes the step
    • Decision Explainer creates a StepLog with the step name and result type (Passed / Failed / NoResult)
    • Decision Explainer fetches the appropriate message template for (ElementType, ResultType)
    • Decision Explainer renders the template by substituting token placeholders with actual resource values from the expression set
    • Decision Explainer saves the rendered ExplanationMessage in the StepLog
  4. Expression set returns: outputs plus the ActionContextCode
  5. User views the record: the Decision Explainer Log History component (added to the record page layout) queries ExplainabilityActionLog by ContextRecordId
  6. Component displays explanations: shows the rendered messages in time order
  7. Compare feature: user selects two or more ActionLogs and clicks Compare to see side-by-side differences

Enabling Decision Explainer on an Expression Set

  1. Expression Set Builder → open the version
  2. Properties panel (gear icon) → enable Show decision explanation
  3. For each step where you want an explanation:
    • Select the step → Element Details panel
    • Enable Show decision explanation
    • Select message templates for:
      • When Step Returns Output (Passed)
      • When Step Errors (Failed)
      • When Step Returns No Output (NoResult — Lookup Table only)
    • If templates use tokens, map tokens to expression set resources (map tokens icon next to the template)
  4. Activate the version

Viewing Explanations in the UI

  1. Add the Decision Explainer Log History component to the record page layout (e.g. Application__c record page in Lightning App Builder)
  2. Run the expression set from a Flow (use runExpressionSet action with Decision Explainer enabled)
  3. Open the record (e.g. the application record)
  4. Decision Explainer Log History component shows:
    • List of expression set runs (by ExecutionDateTime)
    • Each run’s overall outcome
    • Expandable step-by-step explanations

Usage Patterns

Show applicant why they were deniedEnable Decision Explainer on the eligibility expression set; add Log History component to the application record page; applicant views their application and sees “Not eligible: income 45,000exceedsceiling40,000 for household size 2.”
Auditor reviewAuditor opens the application record, views the Decision Explainer Log History, sees the exact steps and values that led to the determination
Compare two runsExpression set ran twice (before and after a data fix); auditor selects both runs in Log History, clicks Compare, sees side-by-side which step changed
Troubleshoot a ruleDeveloper enables Decision Explainer during testing; runs expression set with test inputs; views Log History to see which step produced unexpected output
External API callersThird-party system calls expression set via REST API with actionContextCode and explainabilitySpecName; response includes actionContextCode; system can query /services/data/vNN/connect/business-rules/action-logs/{actionContextCode} to get explanations

Considerations

  • Confidential information: External users see the explanation messages, so avoid exposing sensitive data (e.g. internal policy thresholds, confidential formulas) in templates
  • Performance: Enabling “Explain Subexpression” may impact performance (logs subexpression steps recursively)
  • Token mapping required: If a template uses tokens and you don’t map them, the rendered message shows the raw token (e.g. ${Amount}) instead of the value
  • Disabling after adding messages: Once you add explainability messages to steps, action logs show them even if you later deselect “Show decision explanation” at the version level. To exclude explanations from API responses, omit actionContextCode and explainabilitySpecName from the request.
  • Permissions:
    • Rule Engine Designer — configure explainer, map tokens
    • Decision Explainer Service Access — create message templates and tokens
    • Manage Flows OR View Developer Name — view Decision Explainer Log History component

Example: Student Discount Eligibility

Expression Set: Student_Discount_Eligibility_Check

Step 1 (Lookup Table): Decision Matrix → IncomeCeiling, DiscountPercent

  • Message template (Passed): “Income ceiling is IncomeCeilingforhouseholdsize{HouseholdSize}.”
  • Token mapping: IncomeCeiling → IncomeCeiling variable, HouseholdSize → HouseholdSize input variable

Step 2 (Conditional Group): IF Income > IncomeCeiling

  • Message template (Passed — condition is true): “Not eligible: income Incomeexceedsceiling{IncomeCeiling}.”
  • Token mapping: Income → Income input variable, IncomeCeiling → IncomeCeiling variable

Step 3 (Calculation): FinalDiscount = DiscountPercent * BaseAmount

  • Message template (Passed): “Eligible for DiscountPercent{BaseAmount}. Final discount: ${FinalDiscount}.”
  • Token mapping: DiscountPercent → DiscountPercent variable, BaseAmount → BaseAmount variable, FinalDiscount → FinalDiscount variable

Result in UI:

When a student with household size 2, income $45,000 is processed:

  1. “Income ceiling is $40,000 for household size 2.”
  2. “Not eligible: income 45,000exceedsceiling40,000.”

When a student with household size 2, income $35,000 is processed:

  1. “Income ceiling is $40,000 for household size 2.”
  2. (Conditional Group step not shown — condition was false)
  3. “Eligible for 10% discount on base amount 5,000.Finaldiscount:500.”

The Decision Explainer Log History component on the student record shows both runs; the Compare feature highlights that the first run failed at step 2 (income check) while the second run passed and reached step 3 (calculation).
