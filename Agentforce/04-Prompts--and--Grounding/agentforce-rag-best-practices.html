RAG Overview

RAG (Retrieval Augmented Generation) grounds LLM prompts with accurate, up-to-date enterprise knowledge — files, emails, articles, call notes, object descriptions — retrieved by semantic similarity to a query.

Online runtime flow:

  1. Retriever invoked with dynamic query from prompt template
  2. Query vectorised → semantic search against the search index
  3. Relevant chunks retrieved
  4. Prompt augmented with retrieved content
  5. Resolved prompt submitted to LLM → response generated

Offline preparation:

  1. Connect unstructured data (DSO → DLO/UDLO → DMO/UDMO)
  2. Create search index config → chunk + vectorise content
  3. Store and manage index in Data Cloud

Key components: Search Index → Retriever → Prompt Template → Agent Action

Fastest Path: Agentforce Data Library (ADL)

ADL auto-creates all RAG pipeline components with default settings.

ComponentDefault
Search IndexFileUDMO_SI, hybrid search, 512-token chunks, E5 Large Multilingual
RetrieverReturns 10 results; advanced retrieval off
Prompt Template”Answer Questions with Knowledge” (dynamic retriever)
Agent ActionAuto-created, same name as template

ADL supports: Files (Salesforce-managed storage) and Knowledge Articles only.

Use ADL when the use case fits exactly — fast to set up but limited configurability. Use manual setup for other object types or custom chunking/retrieval needs.

Ensemble Retriever (ADL with both files + knowledge)

When an ADL has both data sources, an ensemble retriever is auto-created. It merges and dynamically reranks results from both sources, surfacing only the most relevant content. Reduces prompt bloat, latency, and cost. #Roadmap Manual bundling of arbitrary retrievers planned.

Designing RAG-Powered Agents

Approach 1 — One prompt template, multiple sources (ensemble)

Use when all data sources are relevant to most questions, or when it’s hard to distinguish which source to call per question type.

Approach 2 — Separate prompt template per data source

Use when agent instructions can clearly distinguish which action to call per question type, and a single source can fully answer the question.

Avoid chaining RAG actions sequentially

Don’t instruct the reasoning engine to call multiple RAG actions in sequence. It may stop early, deeming intent fulfilled before all actions are called.

Both approaches can be combined in the same solution.

Curating Content for RAG

Content quality directly affects retrieval quality. Key guidelines:

  • Detailed and thorough — more context = better retrieval; include synonyms and abbreviations
  • Real-world examples — helps retrieval match user query patterns
  • Well-structured — logical paragraphs, H1–H6 headings (used as chunk delimiters)
  • Spread over fields — use Description, Resolution, Summary etc. separately in Knowledge Articles
  • Alt-text on media — images/video are ignored; their descriptions are indexed
  • Single-topic articles — avoid combining unrelated topics; semantic match degrades
  • Regular audits — stale/incorrect content leads to hallucinations

Intelligent Context (AI-powered curation workspace)

  • Interactive workspace in Data Cloud → Process Content → Intelligent Context
  • Upload sample files, use AI Smart Defaults or manual parsing, test in agent chat, then publish to UDMO
  • Supports prompt-based customisation (e.g. “Extract the drivetrain table as markdown”)
  • Supports multiple lenses on the same document (e.g. Sales lens vs Service lens)

Hybrid Search

Combines vector search (semantic similarity) and keyword search (lexical match) in a single call.

  • Use when: product names, brands, specific terminology, or jargon are critical to retrieval
  • Don’t use as a standalone keyword search engine for categories (micro-chunks degrade semantic results)
  • Tradeoff: ~2× Data Cloud credit consumption + increased latency
  • Popularity and recency ranking factors can be configured in the search index builder

Search Index: Field Selection, Chunking, Vectorisation

Four field roles

RolePurposeIndex type
Index fieldsChunked + vectorised; used for semantic searchDMO only
Prepend fieldsValue prepended to every chunk for context enrichmentDMO only
Filter fieldsAdded to index schema; used to filter search (not vectorised)DMO + UDMO
Return fieldsReturned with results; can come from index DMO or related DMODMO + UDMO

Index field selection rules

  • Only long-form text fields with at least one semantically coherent sentence
  • Avoid categorical/picklist fields — micro-chunks break semantic search
  • Index as few fields as possible; for similar fields, pick the most detailed one
  • Use prepend fields to add title/summary context to every chunk

Chunking strategy

  • Max chunk size: 512 tokens (~400–500 words)
  • Platform uses semantic passage extraction markers, then merges up to configured size
  • Smaller chunks = better precision; larger chunks = more augmentation context

Enriched Indexing (#Roadmap / coming soon)

Generates three chunk types per original chunk:

Chunk TypeContents
PLAINOriginal chunk text
QUESTIONLLM-generated questions that the chunk answers (improves Q&A recall)
METADATALLM-generated keywords, entities, topics, sentiment, title, summary

Prompt augmentation always uses PLAIN chunks; QUESTION/METADATA chunks only improve retrieval.

Embedding Models

ModelUse when
E5 Large V2 (default)English-only content
E5 Large MultilingualMultilingual content; 100 languages; cross-language retrieval
Ada 002Used when enriched chunking is on (E5 models incompatible with enriched chunking)

Retriever Configuration

Default retriever

Auto-created for every search index. Returns 10 results. No advanced retrieval.

Custom retrievers (Einstein Studio)

  • Configure return fields (from index DMO or related DMO)
  • Configure static or dynamic prefilters
  • Dynamic prefilter: Account = $placeholder → mapped to a field value in Prompt Builder at runtime

Prefilter limitation

Cannot add prefilter fields to an existing search index — must be defined at index creation.

Advanced Retrieval Mode #Roadmap

Iterative retrieval with LLM-based query rewriting:

  1. First retrieval using original query
  2. Summarise results
  3. LLM rewrites query using original + summary
  4. Second retrieval with rewritten query → augment prompt

Use when users enter imprecise or high-level queries.

Prompt Engineering for RAG

A minimal prompt (“answer this question using this information”) leads to hallucinations. The out-of-the-box “Answer Questions with Knowledge” template provides:

  1. Instructions to understand the user question
  2. Explicit grounding instructions (only use provided content)
  3. Fallback when content is insufficient (“Sorry, I can’t find an answer…“)
  4. Output formatting and language instructions

Key prompt engineering principles

  • Explicitly instruct the LLM to use only the provided context
  • Specify what to do when context is insufficient
  • Include reasoning and output format instructions
  • More detailed instructions → less hallucination risk

Citations #Roadmap

Two approaches:

ApproachDescription
Platform-managed (recommended)Auto-formats citations; “Sources” section at response end; inline citations for standard actions; available for agents created after May 26, 2025
Instruction-basedCustom prompt instructions for citation format; more context window usage; requires rigorous testing

Setup: Enable citations in the retriever (Einstein Studio), then toggle “Turn on citations” in the Prompt Template’s retriever settings.

Image citations supported — uses image description from enriched processing; appears as external links in agent UI.

Pro-Code RAG (without Retrievers)

Use Apex + Data Cloud Connect API when:

  • Nested prefilter conditions needed
  • Post-retrieval filters required (user access checks etc.)
  • Operators unsupported by no-code retrievers

Automatic summarisation

If Apex/Flow returns content exceeding the context window, the platform auto-summarises it before passing to the LLM.

RAG in Flow

Flow as the orchestration layer instead of the prompt template.

Standard Flow actions for RAG:

  • Detect Language — for dynamic language prefilters
  • Transform Query for Case/Email/Conversation — LLM-based query optimisation (removes greetings, extracts intent)

Retriever output in Flow

Retriever output is JSON (not a supported Flow type). Requires an Apex processor action to flatten it to a String before downstream use.

Selecting the Right LLM

ConsiderationGuidance
Context windowMust accommodate full resolved prompt. GPT-4o/Turbo = 128K tokens; GPT-3.5 = 16K (often insufficient for RAG)
Reasoning capabilityFor complex reasoning over retrieved context → stronger model (GPT-4); for simpler retrieval + generation → smaller model acceptable

Debugging and Troubleshooting

Stepwise chain to check:

  1. Agent layer — is the right topic/action selected? Check in Agentforce Builder
  2. ADL layer — is the right retriever/grounding source passed to the prompt template?
  3. Search index layer — run SELECT * on Index DMO; compare record count vs source DMO count
  4. Retriever layer — check result fields, retriever version in Prompt Builder
  5. Prompt resolution — use ?c__debug=1 URL param in Prompt Builder for resolution-only mode (saves cost + time during debugging)

RAG Quality Metrics

MetricMeasuresDiagnoses
Context RelevanceRetrieved content vs queryRetrieval problems
FaithfulnessResponse grounded in context?LLM generation / prompt problems
Answer RelevanceResponse vs queryOverall RAG quality

Common failure patterns:

  • Low context relevance + low faithfulness → retrieval problem (wrong content fetched)
  • High context relevance + low faithfulness → LLM/prompt problem (ignoring context)
  • High context + high faithfulness + low answer relevance → insufficient context retrieved (increase result count)

Non-Generative RAG Use Cases

  • Semantic similarity search — surface similar cases/articles to a service agent without generating a response; implement via Flow calling a retriever
  • Text classification — vectorise labelled training examples; classify new text by majority vote on top-50 similar results (requires Apex for COUNT-based SQL)

DecisionGuidance
