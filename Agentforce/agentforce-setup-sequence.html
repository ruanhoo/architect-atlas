Phase 1: Foundation Enablement

Pre-requisites before any agent build can begin.

StepFeatureWhat to configureTrailhead
1.1Enable AgentforceSetup → Agents → Enable; understand agent types, conversation credits, and org limitsAgentforce Basics
1.2Einstein Trust LayerReview data masking rules, zero data retention setting, secure gateway; verify org Trust Layer configThe Agentforce Trust Layer
1.3Trusted Agentic AIUnderstand platform guardrail types, trust patterns, and ethical AI constraintsTrusted Agentic AI
1.4Licenses & PermissionsAssign Einstein Copilot User permission set; configure Running User on the agent; confirm conversation credit entitlementArchitect the Right Solution

Blocker

Agentforce Builder is unavailable until Agentforce is enabled and the current user has the Einstein Copilot User permission. Confirm both before starting any build.

Phase 2: Planning & Architecture

Define what the agent will do before touching the builder. This is the only structured methodology Salesforce provides for agent design — skipping it leads to rebuilds.

StepFeatureWhat to doTrailhead
2.1Use CaseDefine agent purpose, success metrics, target users, and channelsIdentify the Agent Use Case
2.2Solution ArchitectureChoose agent type (Service, Sales, Custom), determine required data sources, actions, and integrationsArchitect the Right Solution
2.3GuardrailsDefine scope limits, topics the agent must never handle, and escalation paths to human agentsDefine the Agent Guardrails
2.4Agent Work OutlineMap out topics, sub-intents, required actions, and conversation flowsOutline the Agent’s Work
2.5PrototypeBuild a minimal agent to validate the approach before the full buildPrototype the Agent

Phase 4: Data Grounding

Give the agent access to real data so responses are accurate and current.

StepFeatureWhat to doTrailhead
4.1Data LibraryCreate a file-based Data Library; upload documents (PDFs, articles); expose as a Retrieval action on a topicAgentforce Data Library Basics
4.2Grounding OptionsUnderstand all grounding methods: CRM record context, Data Library, Data Cloud, Prompt TemplatesGrounding an Agent with Data
4.3Data 360 IntegrationConnect Data Cloud to Agentforce; enable unified customer profiles and semantic search on Data Cloud objectsData 360-Powered Agentforce
4.4Advanced RAGBuild Search Index and Retriever in Data Cloud; create grounded Prompt Templates; tune retrieval for accuracyAdvanced RAG with Data 360 and Agentforce

Note

Data Library (file-based) requires no Data Cloud licence. Data 360 RAG requires Data Cloud and is needed for semantic search over large structured datasets.

Phase 5: Customisation

Extend the agent beyond standard configuration.

StepFeatureWhat to doTrailhead
5.1Prompt BuilderBuild Prompt Templates that inject CRM record context into LLM responses; attach templates as agent actionsCustom Service Agents with Prompt Builder
5.2Prompt EngineeringApply few-shot, chain-of-thought, and role-prompting techniques to improve output qualityPrompt Engineering Techniques
5.3Apex ActionsWrite @InvocableMethod classes; expose as agent actions for custom logic not available in standard FlowAgent Customization with Apex
5.4Flow ActionsBuild agent-ready Flows (Autolaunched or Screen Flow); add to topics as actionsAgent Customization with Flows
5.5Programmatic InstructionsAdd variables, conditional logic, and topic filters to Instructions to enforce business rulesProgrammatic Instructions in Agentforce

Phase 6: Testing

Validate agent behaviour before deployment.

StepFeatureWhat to doTrailhead
6.1Conversation PreviewUse Builder’s Conversation Preview panel for interactive ad-hoc testing during the build cycleIntroduction to Agentforce Builder
6.2Testing CentreCreate a Test Suite; define test cases with expected outcomes; use AI to auto-generate tests from agent configAgentforce Testing Center
6.3Testing Tools & StrategiesApply the 5-Step testing strategy; run tests in a sandbox; review action-level pass/fail resultsAgentforce Testing Tools and Strategies
6.4Results & IterationDiagnose action failures; refine Instructions, topics, or actions; re-run until stableView Test Results

Tip

Run Testing Centre after every significant change to Instructions, topics, or actions — not just as a final gate before deployment.
