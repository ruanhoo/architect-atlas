Alphabetical reference of key terms across the Agentforce domain. Each entry gives a concise definition and links to the dedicated note for deeper coverage.

How to use

Use this as a quick-lookup companion during exam prep. Follow [[WikiLinks]] for the full treatment of any concept.

A

Action A discrete capability the atlas-reasoning-engine can invoke on behalf of an agent — the “hands” of the agent. Actions read data, write records, call external systems, or generate content. Types include Flow, Apex, Prompt Template, MuleSoft API Catalog, and custom HTTP. → See agentforce-actions

Agent A configured autonomous worker with a defined role, system-level instructions, a set of Topics, and associated Actions. The agent perceives context, decides which action to invoke, executes it, observes the result, and repeats until the goal is met. → See agentforce-overview

Agent Builder The declarative Salesforce UI (in Setup) used to configure an agent: define role/instructions, create Topics, attach Actions, and test the agent in a conversational preview panel before activation. → See introduction-to-agentforce-builder, customize-agentforce-and-deploy

AgentExchange Salesforce’s marketplace for pre-built agent components (Topics, Actions, agent templates) from Salesforce and third-party partners. Equivalent of AppExchange for agent building blocks. → See agentexchange-quick-look

Agentforce Salesforce’s platform for building and deploying autonomous AI agents that reason, plan, and act across Salesforce data and external systems. Built on the atlas-reasoning-engine, natively embedded in the Salesforce Platform, and governed by the einstein-trust-layer. → See agentforce-overview, introduction-to-agentforce

Agentforce Conversation The licensing unit for Agentforce: one end-to-end interaction from first user message to resolution or handoff. A single conversation can span multiple reasoning steps and action calls; these do not multiply the conversation count. → See agentforce-licensing

Agentforce Sales Coach A pre-built agent type that provides role-play simulations, deal coaching, and call debrief assistance for sales reps. → See agentforce-overview, sell-smarter-with-agentforce

Agentforce Sales Development Representative (SDR) A pre-built agent type for outbound prospecting and lead nurturing via email, operating autonomously without a human sending each message. → See agentforce-for-sales-quick-look

Agentforce Service Agent A pre-built agent type for autonomous customer-facing support. Replaces or augments einstein-bots and handles varied, multi-step service interactions. → See agentforce-for-service-module, agentforce-vs-einstein-bots

Atlas Reasoning Engine The orchestration layer inside Agentforce that drives the agent’s decision loop: Observe → Plan → Act → Observe → repeat. Selects which action to call, in what order, and when the task is complete. Customers configure it via Topics and Actions — they do not train or fine-tune it. → See atlas-reasoning-engine

Audit Trail (LLM) A log of all LLM interactions produced by the einstein-trust-layer, enabling compliance review of inputs, outputs, and data masking events. Separate from the standard Salesforce Setup Audit Trail. → See einstein-trust-layer

C

Channel The surface through which users interact with an agent — for example: Messaging (SMS/WhatsApp), Experience Cloud chat, Slack, email, or voice. Configured during agent deployment. → See agentforce-overview, deploy-agent-to-slack, agentforce-on-mobile-quick-look

Context Window The finite block of text passed to the LLM per call, containing the system prompt (role/instructions/topic), conversation history, and grounded data. Size limits constrain how much retrieved data can be injected per reasoning step. → See atlas-reasoning-engine, data-grounding-and-data-cloud

Conversation → See Agentforce Conversation

Custom Agent A purpose-built agent configured from scratch in Agent Builder for any business process, as distinct from pre-built agent types (Service Agent, SDR, Sales Coach). → See agentforce-overview, customize-agentforce-and-deploy

D

Agentforce Data Library A Salesforce feature that allows agents to search, retrieve, and reason over unstructured content (documents, PDFs, files) stored in Salesforce — without requiring a Data Cloud licence. Files are indexed and made searchable via vector embeddings, enabling RAG-style retrieval directly from native file storage (e.g., Salesforce Files, SharePoint via connector). Distinct from data-cloud-agentforce-context grounding: Data Library covers document/file retrieval; Data Cloud covers structured unified profiles and calculated insights.

CTA angle

Use Data Library when the grounding requirement is document-based (manuals, SOPs, policy docs) and Data Cloud is not licensed or not warranted. Use Data Cloud when real-time unified customer profile data across source systems is the requirement.

→ See data-grounding-and-data-cloud, manage-your-agents-data, ground-your-agent-with-data

Data Cloud (Agentforce context) Salesforce’s real-time data platform, used as a grounding source to inject the unified-individual profile into the agent’s context window. Required when the use case demands personalised, 360-degree responses drawing on data from multiple source systems. → See data-grounding-and-data-cloud, ground-your-agent-with-data

Data Processing Agreement (DPA) The contractual instrument through which LLM providers commit to zero data retention of Salesforce customer data. Enforced by the einstein-trust-layer; not reliant on provider settings alone. → See einstein-trust-layer

Dynamic Data Masking An einstein-trust-layer capability: PII and admin-designated sensitive fields are tokenised before being sent to the LLM, then de-tokenised on return — so raw sensitive data never leaves the Salesforce boundary. → See einstein-trust-layer

E

Einstein Bots Salesforce’s rule-based / NLU-intent chatbot platform, predating Agentforce. Dialogs follow scripted flows; responses are deterministic. Priced on a separate conversation credit entitlement from Agentforce. → See agentforce-vs-einstein-bots

Einstein Search Salesforce’s semantic search engine used to retrieve Knowledge Articles (and other content) as a grounding source via retrieval-augmented-generation. → See data-grounding-and-data-cloud, atlas-reasoning-engine

Einstein Trust Layer Salesforce’s security and governance framework that sits between the platform and external LLM providers. Core capabilities: zero data retention, dynamic data masking, toxicity detection, audit trail, and secure gateway routing. Applies to all Einstein generative AI features, not only Agentforce. → See einstein-trust-layer, agentforce-security-and-permissions

F

Flow Action The most common Agentforce action type: an autolaunched Salesforce Flow exposed as an invocable action. No-code, reusable, testable, and bulk-safe. Preferred when Flow is capable of meeting the requirement. → See agentforce-actions

G

Grounding The process of injecting relevant, real-time data into the agent’s context window before an LLM call, enabling accurate and context-specific responses. Sources include Salesforce records, Knowledge Articles, data-cloud-agentforce-context, and external data via MuleSoft. → See data-grounding-and-data-cloud, atlas-reasoning-engine

H

Hallucination A response generated by an LLM that is plausible-sounding but factually incorrect or invented. Mitigated in Agentforce by: grounding with real data (RAG), constraining the agent to a configured action set, and the atlas-reasoning-engine’s guardrails. → See atlas-reasoning-engine, data-grounding-and-data-cloud

Handoff The mechanism by which an Agentforce agent transfers a conversation to a human agent in Omni-Channel when confidence is low, the user requests it, or escalation rules are met. Shares the same Omni-Channel routing infrastructure as einstein-bots. → See agentforce-overview, atlas-reasoning-engine

I

Instructions Natural-language guidance written by admins/developers at two levels: (1) agent-level role instructions (system prompt); (2) topic-level instructions that constrain what the agent should and should not do within a topic. Instructions are the primary lever for shaping agent behaviour. → See agentforce-overview, programmatic-instructions-in-agentforce

@InvocableMethod The Apex annotation that exposes an Apex class method as an invocable action, callable from Flows and Agentforce. Used when Flow cannot meet the requirement (e.g., complex logic, callouts with custom error handling). → See agentforce-actions

Iteration Cap A configurable limit on the maximum number of reasoning steps the atlas-reasoning-engine can execute for a single user message, preventing runaway loops and uncontrolled cost. → See atlas-reasoning-engine, agentforce-licensing

L

Large Language Model (LLM) A deep learning model trained on large text corpora, capable of natural language understanding and generation. Agentforce uses LLMs (via the einstein-trust-layer gateway) as the reasoning core. Salesforce partners with providers such as OpenAI, Anthropic, and Azure OpenAI. → See large-language-models, einstein-trust-layer

M

MuleSoft API Catalog Action An Agentforce action type that invokes a REST API governed and catalogued through MuleSoft Anypoint Platform. Preferred when the external system is already integrated via Anypoint, or when API governance, rate-limiting, and multi-agent reuse are required. → See agentforce-actions, MuleSoft & Middleware Positioning

N

Natural Language Understanding (NLU) The intent-classification layer used by einstein-bots to map user input to scripted dialog flows. NLU intents do not automatically map to Agentforce Topics — topic design requires rethinking, not just migration. → See agentforce-vs-einstein-bots, natural-language-processing-basics

O

Omni-Channel Salesforce’s routing and queue management framework. Used by Agentforce for escalation/handoff to human agents; shared infrastructure with Einstein Bots transfers. Not part of the reasoning loop itself. → See agentforce-overview, agentforce-vs-einstein-bots

P

Prompt Builder The Salesforce declarative tool for creating and managing reusable prompt templates with dynamic merge fields. Templates are used as Agentforce actions (Prompt Template action type) for LLM-generated content such as case summaries, draft emails, or field generation. → See prompt-builder-basics, get-hands-on-with-prompt-builder

Prompt Template A managed, versioned template created in Prompt Builder. Combines static instructions with merge fields (record data, related data) to form a well-structured LLM prompt. When used as an Agentforce action, token consumption counts toward Einstein quotas. → See prompt-builder-basics, prompt-fundamentals

R

Retrieval-Augmented Generation (RAG) The pattern of retrieving relevant documents or records at query time and injecting them into the LLM context window, so the model reasons from real data rather than training knowledge alone. Core grounding mechanism in Agentforce. → See data-grounding-and-data-cloud, atlas-reasoning-engine

Role (Agent) The agent-level definition of what persona and purpose the agent has — expressed as a system-level instruction. Sets the agent’s overall behaviour and constraints before any topic or action is considered. → See agentforce-overview, introduction-to-agentforce-builder

S

Secure Gateway The einstein-trust-layer component that routes all LLM API calls through a Salesforce-controlled gateway, ensuring no direct client-to-LLM communication and enabling masking/audit on every call. → See einstein-trust-layer

System Prompt The full instruction block passed to the LLM at the start of each reasoning step, composed of: agent role instructions + topic instructions + retrieved grounding data. Admins influence this via Instructions; they do not write raw system prompts. → See atlas-reasoning-engine, agentforce-overview

T

Token The unit of text consumed by an LLM (roughly ¾ of a word). Prompt Template actions and grounding data contribute to token consumption, which is tracked against Einstein quota/limits. → See large-language-models, agentforce-licensing

Topic A cluster of related intents or tasks the agent can handle, each with its own natural-language instructions and a set of associated Actions. Topics map to a segment of the system prompt. An Action can belong to multiple Topics. → See agentforce-overview, agentforce-actions

Toxicity Detection An einstein-trust-layer capability that scans both user inputs and LLM outputs for harmful content, blocking toxic responses before they reach users. → See einstein-trust-layer

U

Unified Individual Data Cloud’s merged, deduplicated customer profile that consolidates identity and behavioural data from all connected source systems. When used as an Agentforce grounding source, gives the agent a real-time 360-degree view of the customer. → See data-grounding-and-data-cloud, data-fundamentals-for-ai

V

Vector Search A semantic similarity search technique used by einstein-search to retrieve Knowledge Articles relevant to a user query. Complements structured SOQL retrieval for unstructured knowledge content. → See data-grounding-and-data-cloud

Z

Zero Data Retention The contractual commitment (enforced via dpa) that LLM providers will not store or train on Salesforce customer data submitted through the einstein-trust-layer gateway. → See einstein-trust-layer
